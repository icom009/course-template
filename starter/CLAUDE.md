## 모든 차시는 4단계 구조를 따른다 (필수)

차시 콘텐츠(slides, examples, labs)는 항상 다음 4단계 흐름으로 작성합니다:

1. **⚠️ 이전 버전의 불편** (`.pain-point`) — "어디가 아팠는가" 를 학생이 직접 체감
2. **🛠️ 새 도구 소개** (`.new-tool`) — 비유 + 어떤 점을 풀어주는가
3. **💻 코드 적용** — 같은 화면을 다시 만든다
4. **🔄 Before / After 비교** (`.before-after`) — "데이터 흐름이 어디가 달라졌나"

이전 버전이 없는 도입부 차시에는 ① 자리에 **"왜 이게 필요한가"** 를 둡니다.

### 1. 흐름도(Flow Diagram) 슬라이드 — 마지막 직전 위치


- `.flow-diagram` 클래스 사용

- 전체 흐름도 중 이번 차시가 닿는 부분을 색으로 강조
- 코드를 만지기 전에 **"내가 지금 어디를 만지는가"** 를 먼저 인식

## 코스 식별: 비주얼 아이덴티티 · 로고 · 공개 상태

> **🆕 원칙(2026-07-29 확정)**: 이 스캐폴드의 CSS 4종(`slides/css/custom.css` 등)을 복제한 뒤 **accent 변수 1~2개만 바꾸고 끝내지 마세요.** 실제로 여러 코스가 이 방식만 쓴 결과, 배경·카드·그림자·타이포는 전부 동일한데 강조색 하나만 다른 "표면만 다른 사이트"가 됐습니다(다크 베이스 전체가 동일 → 학생 입장에서 과목이 바뀌어도 화면이 똑같아 보임). **비주얼 아이덴티티는 코스마다 새로 설계**하는 게 기본값입니다.

### ① 비주얼 아이덴티티 — 비유 사전에서 도출한다

새 코스를 시작할 때 이 순서로 갑니다:

1. **먼저 「핵심 비유 사전」과 「버전 진화 지도」를 채운다** (아래 §비유 컨벤션 참고). 색은 여기서 나온다 — 코스가 카페 비유를 쓰면 커피 톤, 인프라/건물 비유를 쓰면 블루프린트 톤, 이런 식.
2. 비유 사전에서 **4~6개의 이름 붙은 색**(배경 · accent · 보조색 · 텍스트)을 뽑는다. "그냥 예쁜 색"이 아니라 **이 코스의 세계관에서 나온 색**이어야 한다.
3. `:root` 변수를 **다크 베이스(`--bg`, `--surface`)를 포함해서** override 한다. accent만 바꾸는 게 아니라 배경 톤 자체를 코스 세계관에 맞게 옮긴다 (그래도 명도·대비는 다크 테마 가독성 기준을 지킬 것 — reveal.js night 수준의 대비).
   ```css
   :root {
     --bg:      #1B140E;  /* 예: 카페 비유 코스라면 블루블랙 대신 에스프레소 브라운 */
     --surface: #241A12;
     --accent:  #B8703C;  /* 1차 색 — 비유에서 나온 브랜드 메인 */
     --red:     #EA2D2E;  /* 2차 색 — 히어로 그라디언트 끝점, 마일스톤 뱃지 (필요시) */
   }
   ```
4. 카드·박스의 **형태**(모서리 둥글기, 그림자, 여백)도 코스 성격에 맞게 조정 가능하다 — 색만 바꾸는 것보다 형태까지 건드리면 확실히 다른 사이트로 읽힌다. 단, 레이아웃 골격(그리드 구조·타이포 크기 체계·반응형 브레이크포인트)은 검증된 값이니 그대로 둔다.
5. **다른 코스의 `:root` 값을 그대로 베끼지 않는다.** `/home/programs/edu/<다른코스>/slides/css/custom.css` 를 참고하되, 그 코스가 이미 쓰고 있는 배경/accent 조합과는 확실히 다른 값을 고른다 — 특히 다크 베이스 톤(브라운/네이비/그린/차콜 등 색상 계열 자체)이 겹치지 않게.

### ③ 차시 단계별 공개 (admin/locked)

**왜**: 강의가 진행 중일 때 학생이 다음 차시 자료를 미리 보면 흐름이 깨집니다. 차시 끝날 때마다 강사가 그 카드만 "공개" 로 바꾸는 점진 공개 방식.

**작동**:

```html
<!-- 미공개 — 학생: 흐리게 + 🔒 + 클릭 비활성 -->
<div class="card" data-status="locked"> ... </div>

<!-- 공개 — 학생: 정상 노출 -->
<div class="card" data-status="released"> ... </div>
```

**공개 흐름** (강사):

1. 차시 끝남 → 학생이 그 자료 봐도 됨
2. `index.html` 의 해당 카드 `data-status="locked"` → `"released"` 로 변경
3. 저장 (정적 사이트면 즉시 반영, git repo 면 commit + push)
4. 학생은 새로고침하면 잠금 해제된 카드를 봄

**미리보기 (admin 모드)**: 강사가 잠긴 카드 포함 모두 보고 싶을 때 `?admin=smhrd` 를 URL 에 붙이면 비번 prompt → 인증 후 모든 카드 보임 (sessionStorage 저장, 탭 닫을 때까지 유지). 비번은 `index.html` 하단 `<script>` 의 `ADMIN_PW` 상수로 변경 가능.

**원칙**: 공개 여부는 **HTML 의 data 속성** 으로 박힌 정적 상태입니다. 학생 브라우저에서 자물쇠를 우회하는 게 어렵지는 않으나(F12 → 속성 변경), 의도가 "다음 차시는 아직 안 했어요" 라는 선언적 신호이므로 그 정도면 충분합니다. 강한 보호가 필요하면 서버 사이드로 분기.

## 🚨 주석 표준 (전 강의 공통 · 불변)

> **왜 주석인가:** 주석은 "코드 설명"이 아니라 **학생에게 정보를 「한 번 더」 전달하는 2차 교육 채널**. 슬라이드가 1차(큰 그림)면, **예제(examples) 코드의 주석**이 2차로 재전달하며 **세부 디테일**을 익히게 한다. **주석의 집 = 「예제」** (핸드북 아님 — 핸드북은 요약본).

> **🆕 범위 확장(2026-07-29, 강사 확정):** 이 원칙은 코드 주석에만 갇히지 않는다 — **슬라이드·예제 본문에서 처음 등장하는 개념·용어는 코드가 아니어도 똑같이 친절하게 설명**한다(예: 특정 도구·용어가 왜 필요한지, 무엇인지). 재등장 시엔 짧게 한 줄 why만. "당연히 아는 것"을 가정하지 않는다 — 완전 초보 기준. (배경: dl2 과정에서 코드 밖 개념까지 이 기준으로 풀어쓰며 확인된 원칙. 이 스캐폴드로 새로 만드는 모든 코스에 적용.)

모든 코드 주석은 **2층**:
1. **키워드 「처음 등장」 = 도입 블록 주석** — ① 무엇인지(정의) ② 어떻게 쓰는지(형태·주요 변형값).
2. **이미 배운 키워드 사용처** = 한 줄 「왜(why)」.

**예제 주석의 깊이 = 「기준 참조물 수준 + 더 자세히」** — 반드시 3개 다:
- **① 개념 설명** — 무엇이고 **왜 존재하나** (단순 "이렇게 쓴다" 기능 사용법 그 이상).
- **② 키워드 설명** — 등장하는 키워드(속성·값·기호·API)를 **하나하나** 짚어서.
- **③ 디테일** — 값/인자 형태, 주의점, 헷갈리는 이웃 개념과의 구분.

> 기준 참조물(품질 바닥선): 잘 주석된 강사 원본이 있으면 그걸 바닥선으로 삼고 **거기서 더** 얹는다. (htmlcss = 고선아 zip. 새 코스는 해당 코스의 참조물 지정.)

## 새 차시를 만들 때

1. 해당 차시가 **어떤 버전 진화에 속하는지** 먼저 정한다 (v_n_ → v_(n+1)_)
2. **4 단계 구조** 로 본문을 짠다 (불편 → 도구 → 적용 → Before/After)
3. 슬라이드 마지막 직전에 **흐름도 슬라이드** 를 둔다 (이번에 새로 생긴 칸 강조)
4. examples / labs 첫 페이지에 **미니맵** 을 둔다
5. labs 의 모든 Step 마지막에 **Checkpoint** 를 둔다
6. 마일스톤 차시면 헤더에 **버전 뱃지** 를 단다
7. `index.html` 의 해당 Part 섹션에 **카드 한 장** 을 추가한다 (기호 + 키워드, 차시 번호 없음)

- ❌ 학생 화면에 「**비전공자**」 노출

- ❌ 코스 범위 밖 주제 깊이 도입 (후속 과정으로 미루기)
